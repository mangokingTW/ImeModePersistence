유사 도구

繁體中文 · English · 简体中文 · 日本語 · 한국어

이 필요를 위해 다른 사람들도 만들어 왔습니다 — 하지만 모든 선택지가 어딘가에서 벽에 부딪힙니다. 이 페이지는 문제 → 대안이 막히는 지점 → 이 유틸리티가 그것을 어떻게 넘어서는가 순으로 구성되어 있으며, 이를 통해 이 유틸리티의 강점이 다른 도구들의 고충을 어떻게 해결하는지 볼 수 있습니다.

문제 1: 변환 모드가 아니라 입력 방법/언어를 전환한다

대안들(Windows에 내장된 "각 앱 창에 대해 서로 다른 입력 방법", 대부분의 표시기 도구)은 각 창이 사용한 어떤 입력 방법인지만 기억합니다. 하지만 진짜 성가신 것은 중국어 IME 내부의 고유/영숫자 변환 모드입니다 — Windows는 이를 스레드별로 취급하므로, 창을 전환하면 기본값으로 되돌아갑니다. 영어, 일본어, 중국어 커뮤니티 전반에서 "창을 전환하면 언어가 바뀐다"에 대한 통상적인 조언은 그 내장 설정을 켜라는 것인데, 이는 다른 계층을 관장하므로 부분적인 해결책일 뿐입니다.

이 유틸리티가 넘어서는 방법: 입력 방법뿐 아니라 변환 모드 자체를 추적하여(WM_IME_CONTROL의 IMC_GET/SETCONVERSIONMODE를 통해) 다음 창으로 이어줍니다.

문제 2: AutoHotkey 도구는 안티치트에 차단된다

가장 가까운 동류인 KBLAutoSwitch 및 유사 도구들은 AutoHotkey로 만들어졌습니다. 일반적인 자동화를 위해 AHK는 보통 저수준 전역 키보드 후크를 설치하고 **SendInput**으로 입력을 합성합니다 — 바로 안티치트(EAC / BattlEye / Vanguard)가 감시하는 매크로 시그니처이므로 자주 차단되거나 지목당하게 됩니다; 게임 처리는 다뤄지지 않은 채로 남습니다.

이 유틸리티가 넘어서는 방법: 네이티브 C++로 만들어졌으며 키보드 후크도, 합성된 키 입력도 전혀 없습니다(수동적인 포그라운드 WinEvent만 사용). 매크로 도구처럼 보이지 않으므로 안티치트 게임 안에서도 작동합니다. (검증 가능: src/ 전체에 SetWindowsHookEx, SendInput, keybd_event가 없습니다.)

문제 3: 원시 입력 전체 화면 게임에 닿을 수 없다

내장 설정과 메시지 기법은 키보드를 직접 읽는 전체 화면 게임(예: Helldivers 2)에는 아무런 효과가 없습니다 — 그 게임은 IME 상태 관리에 참여하지 않으며, 실행 파일 경로조차 읽을 수 없습니다.

이 유틸리티가 넘어서는 방법: TSF를 사용해 프레임워크 수준에서 입력 언어를 설정하고, 그런 게임을 창 클래스로 식별하여 영어로 고정합니다(Helldivers 2 가이드 참고).

문제 4: 표시기 도구는 보여주기만 할 뿐 동작하지 않는다

LangIndicator, ImTip, IMEIndicator는 커서 위치나 트레이에 현재 상태를 보여주기만 합니다 — 유지 기능도, 앱 바인딩도 없습니다.

이 유틸리티가 넘어서는 방법: 유지 기능 더하기 앱 바인딩 더하기 커서 표시기를 하나로 합쳤습니다; 표시기는 하나의 선택적 부가 기능일 뿐, 도구의 전부가 아닙니다.

문제 5: 직접 조립해야 하는 스크립트 구성 요소

AHK의 IME 라이브러리(s-show/IME.ahk, eamat의 것 등)는 IME 상태를 읽고 설정하는 구성 요소일 뿐이며, 창별 유지 기능은 직접 작성하고 유지 보수해야 합니다.

이 유틸리티가 넘어서는 방법: 바로 실행 가능한 트레이 유틸리티입니다 — 설치하면 작동하며, 작성하거나 계속 살려둘 스크립트가 없습니다.

한 줄로

일상적인 중국어/영어 전환에 표시기까지라면 KBLAutoSwitch 같은 도구들이 이미 성숙합니다. 하지만 창 간 변환 모드 유지, 안티치트 게임 안에서의 사용, 또는 AutoHotkey에 의존하지 않기를 신경 쓰기 시작하는 순간, 이 유틸리티가 그 세 가지 벽을 넘어서도록 만들어진 도구입니다.
