類似ツール

繁體中文 · English · 简体中文 · 日本語 · 한국어

この需要のために作られたツールは他にもあります。しかし、どの選択肢もどこかで壁にぶつかります。このページは 問題 → 代替ツールがつまずくところ → このユーティリティがどう乗り越えるか という構成になっており、その強みが他ツールの痛点にどう答えるかが分かるようになっています。

問題 1: 入力方式／言語を切り替えるが、変換モードは切り替えない

代替ツール（Windows 内蔵の「アプリウィンドウごとに異なる入力方式」や、ほとんどのインジケーターツール）は、各ウィンドウがどの入力方式を使ったかを記憶するだけです。しかし本当の苛立ちは、中国語 IME の 内部 にある かな／英数の変換モード です。Windows はこれをスレッドごとに扱うため、ウィンドウを切り替えると既定へ戻ってしまいます。英語、日本語、中国語の各コミュニティで「ウィンドウを切り替えると言語が変わる」への定番の助言は、この内蔵設定を切り替えることですが、これは部分的な解決にすぎません。別の層を制御しているからです。

このユーティリティがどう乗り越えるか: 変換モードそのもの を（WM_IME_CONTROL の IMC_GET/SETCONVERSIONMODE によって）追跡し、次のウィンドウへ引き継ぎます。単なる入力方式ではありません。

問題 2: AutoHotkey ツールはアンチチートにブロックされる

最も近い同種のツールである KBLAutoSwitch などは、AutoHotkey 上に作られています。一般的な自動化のために、AHK は通常 低レベルのグローバルキーボードフック をインストールし、SendInput で入力を合成します。これはまさにアンチチート（EAC / BattlEye / Vanguard）が警戒するマクロの特徴であり、しばしばブロックされたり、フラグを立てられたりします。ゲームへの対応は手つかずのままです。

このユーティリティがどう乗り越えるか: ネイティブ C++ で、キーボードフックも合成キー入力もまったく使いません（パッシブなフォアグラウンド WinEvent のみ）。マクロツールには見えないため、アンチチートゲームの中でも動作します。（検証可能: src/ 全体に SetWindowsHookEx、SendInput、keybd_event はありません。）

問題 3: 生入力のフルスクリーンゲームに届かない

内蔵設定やメッセージによる小技は、キーボードを直接読み取るフルスクリーンゲーム（例: Helldivers 2）には何の効果もありません。そのゲームは IME の状態管理に関与せず、実行ファイルのパスさえ読み取れないからです。

このユーティリティがどう乗り越えるか: TSF を使ってフレームワークレベルで入力言語を設定し、そうしたゲームを ウィンドウクラス で識別して英語に固定します（Helldivers 2 ガイド を参照）。

問題 4: インジケーターツールは表示するだけで、動作しない

LangIndicator、ImTip、IMEIndicator は、カーソル位置やトレイに現在の状態を 表示 するだけです。維持もアプリバインドもありません。

このユーティリティがどう乗り越えるか: 維持 に加えて アプリバインド、さらに カーソルインジケーターを 1 つに統合しています。インジケーターは任意の付加機能の 1 つにすぎず、ツールの全体ではありません。

問題 5: 自分で組み立てなければならないスクリプトの部品

AHK の IME ライブラリ（s-show/IME.ahk、eamat のものなど）は、IME の状態を読み書きするための部品にすぎません。ウィンドウごとの維持は、自分で書いて保守することになります。

このユーティリティがどう乗り越えるか: すぐに使えるトレイユーティリティです。インストールすれば動作し、書いたり生かし続けたりするスクリプトはありません。

一言でいうと

日常的な中国語／英語の切り替えとインジケーターだけなら、KBLAutoSwitch のようなツールはすでに成熟しています。しかし、ウィンドウをまたいだ変換モードの維持、アンチチートゲームの中での使用、あるいは AutoHotkey に依存しないこと を重視した瞬間から、その 3 つの壁を突破するために作られたのがこのユーティリティです。
